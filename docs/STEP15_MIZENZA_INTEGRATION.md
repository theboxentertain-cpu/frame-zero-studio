# MIZENZA — Step 15 integration and staging runbook

Status: development branch only. No production migration, deployment, or AI generation.

## Scope

- Preserves the November 6 MIZENZA branding, Director, four worlds and P00–P23 routes on main.
- P12 provides shot-linked **manual image references** (JPEG/PNG/WebP imports).
- Images are decoded and re-encoded to WebP in the browser, hashed, and saved privately under:
  \`<user-id>/<project-id>/stills/<shot-id>/<random-id>.webp\`.
- All image imports require a human-entered rights/provenance note.
- Shot plans must remain approved/current before images can be attached or reviewed.
- Manual frame review **does not** approve the generated film-stills gate.
- JSON handoff contains direction text only; generation status remains \`not_generated\`.

## Database deployment boundary

The **separate** staging project \`crvgvcokzryoxyvjkhxn\` already has migrations 0000–0005 committed. **Do not replay 0000–0005.** Migration 0006 is the only new forward-only SQL change; it adds the gate/revocation checks to existing Step 15 review and attachment RPCs.

The Lovable production backend does **not** have the storyboard table or the 0002 security restrictions. A GitHub merge is **not** equivalent to a production database migration. No production migration is authorized by this PR.

Never run \`drizzle-kit push\`: \`drizzle/schema.ts\` is an empty autogenerated stub. Run reviewed SQL migrations and verify against a known staging snapshot.

## Staging acceptance gates

1. Review and apply 0006 on **staging only**, with a transaction, no production access.
2. Verify Supabase Storage bucket \`project-files\` is private and owner scoped.
3. Authenticate two independent users with non-admin public API keys.
4. Confirm user B cannot query, import, review, delete or sign a reference belonging to user A.
5. Confirm stale or revoked shot-list approval prevents attaching or reviewing a reference even when underlying scene/shot versions are unchanged.
6. Confirm scene or shot edits make dependent references stale.
7. Confirm stale optimistic version updates are rejected and local unsaved directions remain recoverable.
8. Confirm manual references do not unlock \`film_stills\`, \`motion\` or \`final_cut\` gates.
9. Exercise English/Arabic mobile flows, uploaded still preview, reload and export with real authenticated accounts.
10. Audit image retention/orphan cleanup, source licensing, media quality and an independent provider integration before advertising image generation.

## Test coverage and limitations

- \`npm run check\`: TypeScript, ESLint/Prettier, UI unit tests, isolated PGlite database tests, build.
- \`npm run test:browser\`: fixture-backed browser interaction, **not** live Auth or private Storage evidence.
- \`node tests/live-staging.mjs\`: optional dedicated staging Auth/RLS check when six secure env values exist. This tests written projects, **not** the full still-import flow.
- PGlite storage tests insert storage metadata without actual upload; these are not proof of Storage API security, actual byte integrity or signed URL expiry.
- The browser SHA-256 is a *client claim*; the database currently validates its format, not the hash of actual stored bytes.
- No image, video, voice or editing provider is connected. Generated art/footage remains unavailable.

## Release sequence

Pass CI on current branch -> run staging Auth/RLS checks -> apply and validate 0006 on staging -> live mobile and object-storage verification -> reviewed backend migration plan for Lovable production -> merge with branch protection and deployment coordination.

Do not merge or deploy merely because a static preview or a PGlite test passes.
